## 2. 문제점 4건 (실측)

- **문제점 #1 — 도구성 커밋의 정의·권리자·VERSION 병합 규칙 부재**: "버전 상승 없이 허용하지 않는다"와 "도구성 커밋(버전 기록·문서 지도 한 줄)"이 동일 커밋을 지칭 → 모순, VERSION/CHANGELOG를 변경할 권리자·시점 미정의.
- **문제점 #2 — 병렬 브랜치 버전 경합 시 태그 유실 / 부분 상승 실패**: 같은 버전을 두 브랜치가 예약 → 두 번째 머지가 `tag already exists`로 실패하며 버전 미부여 상태 유실 (실현: `fatal: tag 'v1.0.0' already exists`) → 재결정·강제 덮어쓰기·미부여 기록 정책 중 선택 필요.
- **문제점 #3 — PATCH/MINOR 예시 경계 모호**: "테스트·CI 수정"이 PATCH에 있으나 "새 검사 추가"는 MINOR — "새로 추가"와 "수정"의 키워드 1단어로 분류가 갈림 → 임의 분류 가능.
- **문제점 #4 — 태그 부여 실패·누락을 감지할 사후 검증 부재**: 절차 4는 "태그 부여+푸시"만 규정 — 재태그 시도는 `fatal: tag 'vX.Y.Z' already exists`(exit 128, 실재현)로 드러나지만 "부여 자체를 안 한" 경우는 무증상 → 버전 미반영이 발견되지 않고 지나갈 수 있음.

## 3. 개선점 4건 (근거: 위 실측 — 지원 없이 제안 없음)

- **개선점 #1 (문제점 #1 → 해결)**: VERSIONING.md에 "버전 상승 기록(VERSION/CHANGELOG)은 피처 커밋에 포함한다(독립 도구 커밋 생성 금지)"로 명문화 — 도구 커밋 경로를 1개로 폐쇄.
- **개선점 #2 (문제점 #2 → 해결)**: 병렬 브랜치 경합은 "모든 후보를 최고 단계로 버전 갱신(중복 허용) 후 최저 미사용 버전으로 태그"로 명문화 — 태그는 머지 후 최후 1회 부여라 손실 0.
- **개선점 #3 (문제점 #3 → 해결)**: PATCH 열 "테스트·CI 수정"을 "테스트·CI 수정(신규 테스트 추가 포함)"로 명시해 "새 검사 추가"와 경계 확정.
- **개선점 #4 (문제점 #4 → 해결)**: 절차에 "머지 후 `git ls-remote --tags origin vX.Y.Z`로 존재 확인" 1줄 추가 — 태그 누락 사후 검증.

## 4. 반영 제안 (VERSIONING.md 개정 4건 — 현재 문구 실측 인용 기준)

1. §2 "도구성 커밋(버전 기록 자체·문서 지도 한 줄)은 버전 상승 없이 같은 버전 내에서 허용하지 않는다 — **버전 상승과 함께** 커밋한다" → "버전 상승 기록(VERSION/CHANGELOG 갱신)은 변경 PR의 피처 커밋에 포함한다 — 독립 도구성 커밋 생성 금지"로 교체 (개선점 #1).
2. §3 절차 1~3 "변경 PR이 main에 머지되면 새 버전 결정 → VERSION 갱신 → CHANGELOG 추가" → "버전 결정·갱신은 변경 PR에 포함해 머지"로 정렬 (개선점 #1·#2).
3. §2 표: PATCH 예 "테스트·CI 수정" → "테스트·CI 수정(신규 테스트 추가 포함)"로 명시 (개선점 #3).
4. §3 절차 4 "머지 후 머지 커밋에 `git tag vX.Y.Z` 부여, `git push origin vX.Y.Z`" 끝에 "→ `git ls-remote --tags origin vX.Y.Z` 존재 확인" 추가 (개선점 #4).

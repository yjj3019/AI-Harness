# VERSIONING.md — 저장소 버전 체계

## 목적

이 저장소의 소스 변경에 버전(semver `X.Y.Z`)을 부여하고 `docs/CHANGELOG.md`에 기록한다.
버전 변경은 라이선스 감사 규율(소스+라이선스+방식 기록)과 같은 헌법 규칙이 아니다 — 기록 규율이다.
태그는 머지 커밋에 `vX.Y.Z`로 붙인다.

## 버전 상승 기준 (트리거)

| 상승 | 언제 | 예 |
| --- | --- | --- |
| **PATCH (Z+1)** | 소스·문서 변경이 main에 머지될 때 — 최소 상승 단위 | 버그 수정 · 문서·테스트·CI 수정(신규 테스트 추가 포함) · 라이선스 표기/감사 보완 · 아티팩트 갱신(카탈로그·상태·대시보드) |
| **MINOR (Y+1, Z=0)** | 기능 추가 또는 행동 변경 | 새 스킬·스크립트·게이트 추가 · 기존 기능의 동작 변경 · 새 검사 추가 |
| **MAJOR (X+1, Y=0, Z=0)** | 호환성 파괴 또는 헌법 변경 | Primary Rules(AGENTS.md·CLAUDE.md) 변경 · 구조 재편 · 기존 계약(게이트 계약·문서 계약) 파기 |

- 1개 PR이 혼합 변경이면 **가장 높은 단계**를 적용한다 (PATCH+MINOR 혼합 → MINOR).
- 버전 상승 기록(`VERSION`·`CHANGELOG` 갱신)은 변경 PR의 피처 커밋에 포함한다 — **독립 도구성 커밋 생성 금지**.
- 미추적 산출물(예: `docs/practice/`)과 태그/브랜치만의 변경은 버전 대상 아님.

## 절차

1. 변경 PR의 피처 커밋에 버전 상승 기록(`VERSION` 파일 갱신 · `docs/CHANGELOG.md`에 `## [X.Y.Z] - YYYY-MM-DD` 항목 추가, 변경 요약 + 실측 근거)을 포함한다 — 독립 도구성 커밋 생성 금지. 병렬 브랜치가 같은 버전을 예약한 경우 중복 예약을 허용하고, 태그는 최저 미사용 버전으로 부여한다.
2. main 머지 후 머지 커밋에 `git tag vX.Y.Z` 부여, `git push origin vX.Y.Z`.
3. `git ls-remote --tags origin vX.Y.Z`로 태그 존재를 확인한다.

## 입력과 측정

같은 커밋의 `docs/PHASES.md`, `.github/required-phases.json`, `docs/attestations/phase-evidence-baseline.json`과 생성기·파서 두 파일을 Git 객체에서 꺼냈다. 모드별 임시 폴더에서 초기 생성과 예열을 한 번씩 끝낸 다음 각 모드를 열 번 실행했다. 홀수 회차는 강제 재생성이 먼저, 짝수 회차는 기본 모드가 먼저다. Windows 11 빌드 26300, AMD64, Intel Family 6 Model 183, Python 3.15.2, Node v26.13.0을 사용했다. 시간은 Python `perf_counter_ns`로 잰 새 Node 프로세스의 시작부터 종료까지이며, 입력 준비와 결과 대조 시간은 제외했다.

## 동작 비교와 복구

| 입력 상태 | 두 모드에서 관찰한 결과 |
|---|---|
| 처음 생성, 변경 없는 재호출 | 상태 1개. 종료 코드 0, 결과 파일의 SHA-256은 `ab4a8a1d10eff77869c61f9d55aecae817aa3d0cce22e665b301269f2f75ce98` |
| 기존 출력이 오래된 내용 | 원래의 결과 바이트를 복원 |
| 단계 정의와 증명 파일이 모두 비어 있거나 없음 | 출력 바이트가 `[]` |
| 대소문자만 다른 중복 단계 ID | 두 모드 모두 종료 코드 1, 같은 중복 ID 오류 메시지. 직전 출력 `[]` 유지 |
| 입력 복구 후 쓰기 생략 비활성화 | 원래 입력을 되돌리고 `--force`로 실행해 두 임시 폴더 모두 원래 출력 바이트 복구 |

비교한 입력 중 출력 내용이나 오류 계약이 달라진 경우는 없었다. 파일 교체 여부와 수정 시간은 동등성 대상에서 제외했다. 이 사례는 1개 단계, 로컬 파일시스템, 순차 재호출을 다룬다. 큰 인벤토리, 동시 쓰기, 다른 OS, 전체 CI에 대한 효과는 미측정이다.

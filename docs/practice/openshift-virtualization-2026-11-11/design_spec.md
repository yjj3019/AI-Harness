## 내러티브 (Situation → Complication → Resolution)

1. **Situation** — 결정할 것은 기술이 아니라 경계: 레거시 VM과 컨테이너를 한 플랫폼으로 합칠 것인가 (S1~S2)
2. **Complication** — 확인은 F1·F2 두 건뿐, F3·F4는 403으로 미검증 — 증거가 부족할 때 어떻게 말하는가 (S3)
3. **Build** — 개념(한 플랫폼, 두 워크로드, 한 운영) → 배경(4차원 교환) → 판단의 틀(4축, 제안) → 예시 채점 (S4~S7)
4. **Process & Proof** — 8단계 파이프라인(같은 근거표) → 형식별 게이트 결과 (S8~S9)
5. **Resolution** — 한계(미수행/미검증) + 다음 4걸음 → 결정 순서: 재실측 → 실측 채점 → 경계 (S10~S11)
6. **Close** — 확인일 + 근거 없는 수치 0 + 출처 (S12)

**고스트 덱 테스트**: S1~S12 액션 타이틀만 순서로 읽으면 위 내러티브가 성립 (S2→S11 제목 = 결과 문장).

## 비주얼 디렉션

- **원 아이디어**: "근거 문서처럼" — 에디토리얼 헤어라인(2pt 인크 헤더 룰 + 1pt 헤어라인) 위에 타이포 위계만.
- **팔레트**: 인크 #101418 / 페이퍼 #FFFFFF / 단일 액센트 블루 #2563EB. 상태(확인·미검증·제안)는 6~9pt 점 + 트래킹 라벨로만 — 채우기 칩 금지.
- **인크 블록(무게 대비)**: S1 커버 · S12 클로징 · S4 플랫폼 바 · S11 결정 스트립 — 이 4곳 외 인크 채우기 없음.
- **타이포**: Bahnschrift(디스플레이·숫자) / Segoe UI(본문) / Consolas(수치·ID·URL) / Malgun Gothic(EA). 제목 27pt 볼드(액션 타이틀), 섹션 라벨 9~9.5pt 트래킹 대문자, 본문 11~12.5pt.
- **밀도 규칙**: 슬라이드당 인크 블록 ≤1 · 상태 점 ≤5 · 본문 12pt 이하 금지.
- **차트 정책**: 얇은 바(높이 11pt, 단일 블루, 0기점, 헤어라인 베이스라인)만. 무지개·색 상자·라운드 카드 금지.

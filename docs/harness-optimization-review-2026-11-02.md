## Decision and scope

Use these projects as sources of ideas, not as replacements for the current harness or as evidence that a proposed change will improve it. The next step, if separately authorized, is a bounded, independently assessed comparison; there is **no automatic installation, execution, adoption, gate change, or promotion** in this review.

This is a selective static synthesis of the supplied investigation and the pinned references below, not a complete source, dependency, security, license, or operational audit. Descriptions summarize reported patterns rather than verified runtime behavior or comparative results. No upstream tools or benchmarks were executed for this document. A repository's root license does not establish the license of every dependency, model, dataset, bundled component, or linked work; verify applicable terms and notices before reuse. The prose here is original and no upstream code is incorporated.

## Existing capabilities and remaining proposals

The local [paired evaluation diagnostic](paired-evaluation.md) added after this review counts declared outcomes; it does not execute a benchmark, establish independent review, compare costs, or adopt changes. Existing [DeepSeek Team guidance](deepseek-team-workflow.md) uses the runtime's own collaboration instead of replacing it, while the Phase gate and read-tracker remain separate evidence mechanisms. The procedures below are proposals, not automated integrations.

### 1. Independent bounded comparator

If approved, compare the existing baseline against one narrowly specified candidate on the same synthetic or explicitly approved public tasks. Before seeing outcomes, fix task and fixture revisions, scoring rubric, scorer, environment, model and tool versions, budget, retry policy, and all planned pairs; document any differences. Separate development/selection cases from a final held-out set that is not repeatedly consulted for selection. Keep the evaluator and answer key independent of the candidate author where feasible; disclose any overlap or leakage. A separate scorecard alone does not establish independence.

Set host-enforced filesystem, execution, network, time and resource limits appropriate to the approved fixture; do not assume clean directories, prompts, hooks, or editable guardrails provide containment. Use no secrets or live external effects. If enforcement or observation cannot be established, do not run the affected case; record its result as `UNKNOWN`. Preserve all attempts and per-task outcomes, including failures, skips and unknowns; report elapsed and human-review time, cost where observable, safety incidents, and limitations. A no-regression finding means only no *observed* regressions in the completed comparable cases, not proof of universal safety or quality. The existing [evaluation pilot](harness-evaluation-pilot.md) and [paired evaluation diagnostic](paired-evaluation.md) describe relevant local conventions; the diagnostic validates declarations, not independent evidence or authorization.

### 2. Manual failure-to-regression ratchet

Separately, select one reproducible failure and retain its baseline, evidence, and an approved synthetic regression case. Have an independent reviewer assess the proposed narrow fix, legitimate-use behavior, false positives, and any remaining uncertainty. Identify an owner, review date, rollback path, and explicit human adoption decision. Do not modify production gates or promote a change simply because a generated test or score passes.

### 3. Automation and dependency review

Before considering any external package or workflow, review pinned source and updates, dependencies and licenses, installation scripts, secrets and data flow, configured and effective permissions, egress, triggers, human approval, failure/retry behavior, and rollback. Treat retrieved text as untrusted data. A static configuration review cannot establish live permissions or observed runtime effects; mark them `UNKNOWN` until separately verified. Approval of this review is not approval to install, enable automation, send data, or execute external code.
